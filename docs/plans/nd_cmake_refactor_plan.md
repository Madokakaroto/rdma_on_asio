# ND CMake Refactor Plan

## Status

Implemented.

This document is the current Windows/NetworkDirect build model. The older
source-embedded `src/networkdirect.cpp` model is retired.

## Final Model

NetworkDirect's vendored source is not header-only friendly: the implementation
files under `third_party/networkdirect/src/ndutil` are normal `.cpp` files, not
inline `.ipp` files. Therefore rdma_on_asio does not include them from public
headers and does not add a NetworkDirect source wrapper to each executable.

```text
NetworkDirect.cmake
  |
  |-- mc.exe -> generated/networkdirect/ndstatus.h
  |
  +-- MSBuild.exe third_party/networkdirect/src/ndutil/ndutil.vcxproj
        |
        v
      networkdirect-native/<config>-<platform>/ndutil/ndutil.lib

Windows executable targets
  |
  |-- consume NetworkDirect include path
  |-- consume NetworkDirect lib search path
  +-- link ndutil.lib
        |
        +-- default: pragma autolink from nd_autolink.hpp
        +-- ASIO_NO_DEFAULT_LINKED_LIBS: consumer links ndutil.lib manually
```

## Module Rules

`cmake/NetworkDirect.cmake` exposes:

```cmake
init_networdirect()
NETWORKDIRECT_LIB_NAME  # ndutil.lib, for manual-link tests/consumers
```

Internal targets:

```text
rdma_networkdirect_generated_headers
  produces generated/networkdirect/ndstatus.h

rdma_networkdirect_headers
  interface include surface

rdma_networkdirect_native_ndutil
  builds native ndutil.lib after generated headers exist

rdma_networkdirect_backend
  interface target applied by init_networdirect()
  provides _WIN32_WINNT, include paths, lib search path, and build-order deps
```

Rules:

- `NetworkDirect.cmake` always generates `ndstatus.h`.
- `NetworkDirect.cmake` always builds native `ndutil.lib`.
- `NetworkDirect.cmake` does not export `NETWORKDIRECT_SOURCE`.
- `NetworkDirect.cmake` does not add implementation source files to executables.
- `NetworkDirect.cmake` does not inspect or define `ASIO_SEPARATE_COMPILATION`.
- `NetworkDirect.cmake` does not define `ASIO_NO_DEFAULT_LINKED_LIBS`.
- `rdma_networkdirect_backend` provides the library search path, but normal
  default linking is driven by source-level autolink.

## Autolink

`include/rdma/nd/detail/nd_autolink.hpp` is included by `nd_types.hpp`.

It emits:

```cpp
#pragma comment(lib, "ndutil.lib")
```

when all of these are true:

```text
!ASIO_NO_DEFAULT_LINKED_LIBS
_MSC_VER
```

This is independent of `ASIO_SEPARATE_COMPILATION`. Both header-only and
separate-compilation consumers link the same native `ndutil.lib`.

When `ASIO_NO_DEFAULT_LINKED_LIBS` is defined, the executable target is
responsible for manually linking `ndutil.lib` and the Windows/Asio system
libraries it disabled.

## Executable Rules

- Do not compile `src/networkdirect.cpp`.
- Do not include `rdma/nd/impl/networkdirect.hpp`.
- Header-only consumers include normal rdma_on_asio public headers and link
  `ndutil.lib`.
- Separate-compilation consumers define `ASIO_SEPARATE_COMPILATION`, compile one
  TU that includes `rdma/impl/src.hpp`, and still link `ndutil.lib`.
- Targets that define `ASIO_NO_DEFAULT_LINKED_LIBS` manually link
  `NETWORKDIRECT_LIB_NAME` / `ndutil.lib`.

## Verification

Expected checks:

- `generated/networkdirect/ndstatus.h` is generated by `mc.exe`.
- `networkdirect-native/<config>-<platform>/ndutil/ndutil.lib` is produced by
  native `ndutil.vcxproj`.
- No target compiles `src/networkdirect.cpp`.
- Default-link tests do not explicitly list `ndutil.lib`.
- Manual-link tests explicitly list `ndutil.lib`.
- `unit_rdma_separate_compilation` does not compile NetworkDirect sources and
  links through the same `ndutil.lib` path as external consumers.
