# CTest All Tests Plan

## Goal

Move every test-oriented executable under `tests/` into the CTest graph. CTest
will be the unified runner for:

- single-process unit/integration/stress/performance smoke tests;
- two-process echo tests;
- RDMA-on-Asio perftest-shaped bandwidth and latency tests;
- native ND / ibv backend tests;
- external perftest comparison tests when the perftest binaries are available;
- benchmark tooling smoke tests.

The important distinction is:

```text
CTest test case = one CTest command

That command may run:
  - one executable directly;
  - one wrapper executable that launches server + client;
  - one wrapper executable that launches a script/tool workflow.
```

CTest does not need every test to be physically single-process. It only needs
each registered case to be self-contained, bounded by a timeout, and able to
clean up its child processes.

## Principles

1. `BUILD_TESTING` still controls whether `tests/` is added.
2. `tests/CMakeLists.txt` remains the single owner of all test executable
   construction and CTest registration.
3. CMake must not cache local or peer RDMA addresses. Local addresses are
   discovered at runtime through public RDMA-on-Asio APIs.
4. Multi-process CTest cases are driven by a small test runner, not by CTest
   fixtures. CTest fixtures do not keep a setup process alive for the client.
5. Test code should use public `rdma/rdma.hpp` and RDMA-on-Asio APIs by default.
   Direct ND / ibv tests are allowed only under explicit native/backend labels.
6. Every hardware test gets a timeout and a CTest resource lock such as
   `RESOURCE_LOCK rdma_device`, so `ctest -j` does not accidentally overlap
   tests that fight over the same local RNIC or port range.

## Implemented First Pass

The first implementation pass adds:

- `rdma_ctest_runner` for self-contained two-process CTest cases;
- standardized `RDMA_CTEST_READY` output in echo server modes;
- family-specific local RDMA address discovery helpers for `auto-v4` and
  `auto-v6` runner arguments;
- CTest registration for RDMA echo, native backend echo, RDMA-on-Asio bandwidth
  and latency smoke tests, native ND bandwidth and latency baselines, native ND
  compatibility entrypoints, and benchmark tooling smoke tests;
- CTest presets for `echo`, `latency`, `native`, `perftest`, and `tooling`.

On the Windows/NetworkDirect configuration this currently registers 61 tests.
External ibverbs `perftest` binary execution is represented by command-generation
and parser tooling smoke tests in the ND build; full external perftest
server/client execution belongs to the ibv configuration or a machine with those
tools available.

## CTest Process Runner

Add a test-only runner executable, for example:

```text
rdma_ctest_runner
```

Responsibilities:

- launch a server process;
- capture server stdout/stderr to per-test log files;
- wait for server readiness;
- launch a client process;
- capture client stdout/stderr to per-test log files;
- wait for client exit;
- terminate the server if it is still alive;
- fail on timeout, child non-zero exit, missing readiness, or cleanup failure;
- print child log paths on failure.

Suggested CLI shape:

```text
rdma_ctest_runner
  --name TEST_NAME
  --timeout-sec N
  --work-dir DIR
  --resource rdma_device
  --server EXE --server-ready-regex REGEX --server-arg ...
  --client EXE --client-arg ...
```

For CTest:

```cmake
add_test(NAME integration_rdma_echo_event_two_process
  COMMAND rdma_ctest_runner
    --name integration_rdma_echo_event_two_process
    --timeout-sec 30
    --work-dir ${CMAKE_BINARY_DIR}/Testing/Temporary
    --server $<TARGET_FILE:test_rdma_echo>
    --server-ready-regex "RDMA_CTEST_READY"
    --server-arg --server
    --server-arg --port
    --server-arg ${PORT}
    --client $<TARGET_FILE:test_rdma_echo>
    --client-arg --client
    --client-arg auto
    --client-arg --port
    --client-arg ${PORT})
```

The runner should understand `auto` peer addresses by querying the local RDMA
address through public RDMA-on-Asio APIs, then substituting that address into the
client command.

On Windows the runner uses `CreateProcess`; on POSIX it uses `fork`/`exec` or
`posix_spawn`. Avoid shell-specific backgrounding because process cleanup and
quoting become fragile.

## Readiness Contract

Server-style tests should print one standardized line after bind/listen is
complete:

```text
RDMA_CTEST_READY role=server address=<local-rdma-address> port=<port>
```

This should be added to:

- `test_rdma_echo`
- `test_rdma_echo_poll`
- `test_rdma_dual_family_echo`
- `test_nd_echo`
- `test_nd_echo_poll`
- `test_ibv_echo`
- `test_ibv_echo_poll`
- any future server/client benchmark wrapper that does not already have a ready
  line.

Native ND benchmark code already prints `RDMA_BENCH_READY`; the runner can
support both `RDMA_CTEST_READY` and `RDMA_BENCH_READY`.

External perftest binaries may not provide a stable readiness line. For them the
runner should support a conservative fallback:

```text
--server-ready-delay-ms 500
```

This fallback is only for external tools that we do not control.

## Echo CTest Plan

### Backend-Agnostic Echo

Register these under labels:

```text
unit;integration;echo;rdma
```

Cases:

- `integration_rdma_echo_event_two_process`
- `integration_rdma_echo_poll_two_process`
- `integration_rdma_dual_family_echo_two_process`

Execution:

```text
rdma_ctest_runner
  server: test_rdma_echo      --server --port P
  client: test_rdma_echo      --client auto --port P

rdma_ctest_runner
  server: test_rdma_echo_poll --server --port P
  client: test_rdma_echo_poll --client auto --port P
```

For dual-family:

```text
rdma_ctest_runner
  server: test_rdma_dual_family_echo --server --port P
  client: test_rdma_dual_family_echo --client-v4 auto-v4 --client-v6 auto-v6 --port P
```

`auto-v4` / `auto-v6` require a public RDMA-on-Asio helper that can discover a
local RDMA address by family. If one address family is not configured on the
device, keep the test registered but report a CTest skip instead of making the
whole suite fail. If we later decide dual-family support is mandatory on the
target lab machines, flip this from skip to fail.

### Native Backend Echo

Register the active backend's native echo tools under labels:

```text
native;echo;nd
native;echo;ibv
```

Cases:

- ND backend:
  - `native_nd_echo_event_two_process`
  - `native_nd_echo_poll_two_process`
- ibv backend:
  - `native_ibv_echo_event_two_process`
  - `native_ibv_echo_poll_two_process`

These tests intentionally use backend-specific APIs and are the exception to the
public-API-only rule. They should not be labeled `rdma`; they should be clearly
separated as native/backend validation.

## RDMA-on-Asio Perftest CTest Plan

Register every RDMA-on-Asio perftest entrypoint in CTest. Use small smoke values
for the preset cases, and keep larger scenario sweeps as separate scenario
tests.

Labels:

```text
performance;rdma
latency;performance;rdma
bandwidth;performance;rdma
```

Bandwidth smoke matrix:

```text
asio_send_bw   event/callback
asio_send_bw   poll/use_future
asio_write_bw  event/callback
asio_write_bw  poll/use_future
asio_read_bw   event/callback
asio_read_bw   poll/use_future
```

Latency smoke matrix:

```text
asio_send_lat   event/callback
asio_send_lat   poll/use_future
asio_write_lat  event/callback
asio_write_lat  poll/use_future
asio_read_lat   event/callback
asio_read_lat   poll/use_future
```

CTest command shape:

```text
asio_send_lat
  --single-process
  --port P
  --mode event
  --token-type callback
  --topology single_host_same_process
  --message-size 64
  --iterations 64
  --queue-depth 1
  --timeout-sec 30
```

All single-host perftest-shaped cases rely on the executable's runtime address
discovery. CTest should not pass `--local-addr`.

## Scenario Runner Plan

Use `rdma_benchmark_run_scenario` for scenario-level CTest cases.

Labels:

```text
scenario;performance
```

Initial CTest cases:

- `scenario_rdma_on_asio_smoke`
- `scenario_rdma_on_asio_read_write_smoke`

Execution:

```text
rdma_benchmark_run_scenario
  --scenario tests/benchmark/scenarios/smoke.json
  --execute
  --output-dir <Testing/Temporary/scenario-name>
```

The existing runner currently executes only `single_host_same_process`. That is
good for default automation. Two-process and multi-host scenarios should be
delegated to `rdma_ctest_runner` or a future manifest runner that consumes the
server/client commands emitted by `rdma_benchmark_run_scenario`.

## External Perftest CTest Plan

External perftest is a native ibverbs baseline, not an RDMA-on-Asio test.

Labels:

```text
baseline;native;perftest;ibv
```

Use `rdma_benchmark_perftest_commands` to generate the command shape for:

- `ib_send_bw`
- `ib_send_lat`
- `ib_write_bw`
- `ib_write_lat`
- `ib_read_bw`
- `ib_read_lat`

Then use `rdma_ctest_runner` to run the generated server/client commands on one
host when that is supported by the local RDMA stack.

If perftest binaries are unavailable, the registered CTest cases should skip
cleanly with a clear message. This can be done by:

- making the runner check tool availability before launching; or
- adding a thin wrapper that calls `rdma_benchmark_capability_probe` and exits
  with a CTest skip message when tools are missing.

Suggested CTest skip pattern:

```cmake
set_tests_properties(perftest_ib_send_bw_smoke PROPERTIES
  SKIP_REGULAR_EXPRESSION "RDMA_CTEST_SKIP")
```

Multi-host perftest should also be represented through CTest, but not through
CMake cache variables. The runtime interface can be:

```text
ctest --preset perftest-client --test-dir build
```

with runtime environment variables such as:

```text
RDMA_CTEST_PEER_ADDR=<server-rdma-ip>
RDMA_CTEST_ROLE=client
```

That keeps peer addresses out of CMake while still letting CTest drive the
workflow.

## Latency Test Plan

Latency gets its own label and optional preset because latency cases are
performance tests but often need a different command cadence than bandwidth.

Register:

- RDMA-on-Asio latency:
  - `performance_asio_send_lat_event_single_host_smoke`
  - `performance_asio_send_lat_poll_single_host_smoke`
  - `performance_asio_write_lat_event_single_host_smoke`
  - `performance_asio_write_lat_poll_single_host_smoke`
  - `performance_asio_read_lat_event_single_host_smoke`
  - `performance_asio_read_lat_poll_single_host_smoke`
- native ND latency on Windows ND:
  - `baseline_native_nd_send_lat_smoke`
  - `baseline_native_nd_write_lat_smoke`
  - `baseline_native_nd_read_lat_smoke`
- external perftest latency when available:
  - `baseline_perftest_send_lat_smoke`
  - `baseline_perftest_write_lat_smoke`
  - `baseline_perftest_read_lat_smoke`

Latency smoke defaults:

```text
message-size: 64
iterations:   64 or 128
queue-depth:  1
timeout:      30 seconds
```

The executable should return non-zero on failed transport setup or invalid
result. A later quality gate can add JSON assertions for non-null latency fields.

## Benchmark Tooling CTest Plan

Register helper tools with `tooling` labels:

```text
tooling;performance
```

Cases:

- `tooling_capability_probe_smoke`
  - runs `rdma_benchmark_capability_probe --json-out <tmp>`
- `tooling_perftest_commands_smoke`
  - runs command generation for a small send bandwidth scenario
- `tooling_parse_perftest_smoke`
  - parses a checked-in sample perftest stdout file
- `tooling_compare_results_smoke`
  - compares two checked-in or generated sample JSON results
- `tooling_run_scenario_dry_run`
  - runs `rdma_benchmark_run_scenario --scenario ... --json-out ...` without
    `--execute`
- `tooling_run_scenario_execute_smoke`
  - runs a tiny single-host scenario with `--execute`

Tooling tests should not require external perftest unless the case is explicitly
labeled `perftest`.

## Labels And Presets

Keep existing presets:

```text
unit
performance
stress
baseline
```

Add convenience presets only where they reduce command-line friction:

```text
echo       -> label echo
latency    -> label latency
native     -> label native
perftest   -> label perftest
tooling    -> label tooling
```

Suggested preset configurations:

- `unit`: Debug
- `echo`: Debug
- `performance`: Release
- `latency`: Release
- `stress`: Release
- `baseline`: Release
- `native`: Release
- `perftest`: Release
- `tooling`: Release

Labels are composable. For example, native ND latency tests should carry:

```text
baseline;native;native_nd;nd;latency
```

So they can be selected by either:

```text
ctest --preset baseline
ctest --preset native
ctest --preset latency
```

## CMake Helper Functions

Extend `tests/CMakeLists.txt` with focused helpers:

```cmake
rdma_add_ctest_single(NAME TARGET LABELS ARGS TIMEOUT)
rdma_add_ctest_process_pair(NAME LABELS SERVER_TARGET CLIENT_TARGET ...)
rdma_add_asio_performance_smoke(OP METRIC MODE TOKEN ...)
rdma_add_native_nd_smoke(OP METRIC ...)
rdma_add_external_perftest_smoke(OP METRIC ...)
rdma_add_tooling_smoke(NAME TARGET ...)
```

The current `rdma_add_ctest()` can remain as the low-level primitive.

Each helper should set:

```text
LABELS
TIMEOUT
RESOURCE_LOCK rdma_device    for hardware tests
```

## Migration Steps

1. Add `rdma_ctest_runner`.
2. Add a public/test helper for family-specific local RDMA address discovery if
   dual-family CTest needs `auto-v4` and `auto-v6`.
3. Add standardized readiness lines to server-mode echo programs.
4. Add CMake helpers for process-pair CTest cases.
5. Register backend-agnostic RDMA echo event/poll/dual-family tests.
6. Register backend-specific native ND/ibv echo event/poll tests.
7. Expand RDMA-on-Asio performance CTest coverage to all bandwidth and latency
   entrypoints.
8. Expand native ND CTest coverage to all bandwidth and latency entrypoints.
9. Add external perftest CTest coverage with skip-on-missing-tool behavior.
10. Add benchmark tooling smoke tests.
11. Add new CTest presets for `echo`, `latency`, `native`, `perftest`, and
    `tooling`.
12. Run `ctest -N` and verify every test-oriented executable is represented by
    at least one CTest case or explicitly documented as a helper-only target.
13. Run Debug `unit` and `echo`; run Release `performance`, `latency`, `stress`,
    `baseline`, `native`, `perftest`, and `tooling`.

## Verification

- `ctest -N` shows direct, process-pair, performance, native, latency, stress,
  baseline, and tooling cases.
- `ctest --preset echo` runs echo cases through `rdma_ctest_runner`.
- `ctest --preset latency` runs RDMA-on-Asio latency and native latency cases
  where available.
- `ctest --preset native` runs backend-native tests and native baseline tests.
- Missing external perftest tools produce CTest skips, not false failures.
- Failed child processes print their captured stdout/stderr paths.
- Timed-out multi-process tests terminate child processes.
- CMake files still contain no local or peer RDMA address cache variables.
- Automated single-host cases discover local RDMA addresses at runtime through
  public RDMA-on-Asio APIs.
